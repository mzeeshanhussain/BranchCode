Journey Dynamic Deep Link Data Demo

This page reads search-context query parameters directly from the URL and passes them into the Journey deep link via branch.setBranchViewData(). No page-by-page configuration is required — any page using this same snippet will automatically pick up whatever parameters are present in its URL.

Why the close/reapply flow below: branch.init() fires its own automatic pageview to check for Journeys, which can render the banner with default data before our code gets a chance to run. Per Branch's guidance for closing a Journey programmatically, we let that first banner show, immediately close it, wait for the didCloseJourney event to confirm it's safe, then apply our real data and re-trigger the pageview so the banner re-renders correctly. A fixed timeout instead of the event is what causes the race condition where the banner shows generic data.

Supported query parameters (all optional):

  • destination
  • checkin
  • checkout
  • guests
  • rate_code
  • screen — e.g. screen=Settings to route straight to a specific in-app screen instead of a search result
